# 陪伴世界线改造方案（权威规划）

更新：2026-10-28。  
产品聊天主逻辑见 [`CHAT_LOGIC.md`](./CHAT_LOGIC.md)；日常勾选见 [`ROADMAP.md`](./ROADMAP.md)。  
**本文是改造方向文档，不是已实现清单。** 与代码冲突时，先改第 2 节「现状对照」，再改方案。

---

## 0. 目标

**每个人设是一个角色实例。** 基础层保存经历、事实和状态；DSH 结合人设做理解、规划和表达；统一状态入口提交变化，再执行回复、主动消息、朋友圈等行动。

世界线是**可开关的运行层**：开启时，时间、天气、日程和随机事件持续驱动角色生活；关闭时，角色只由对话驱动。

本次四个改造目标：

1. **统一事件流程**：聊天、天气、活动完成、主动消息走同一套事件 → 提议 → 提交 → 行动。
2. **先修记忆写入、纠错与来源**：避免世界线运行后积累错误。
3. **DSH 提出计划与意图，程序校验、提交、执行**：模型输出不直接等于事实。
4. **严格控制每次模型调用的上下文**：长期经历可增长，单次输入有上限。

## 1. 运行模式：世界线开关

### 1.1 定义

每个人设一个开关 `worldline_enabled`，**默认开启**，可在管理台 / App 关闭。

| 能力 | 世界线开启 | 世界线关闭（仅对话驱动） |
|------|-----------|------------------------|
| 时间推进下的生活（作息、日计划、当前活动） | 有 | **无** |
| 天气（真实或模拟）及其对计划的影响 | 有 | **无** |
| 随机扰动（旧照片、活动超时等） | 有 | **无** |
| 每天根据人设自己安排做什么 | 有 | **无** |
| 由世界经历产生的朋友圈 | 有 | **无** |
| 由世界经历产生的主动消息（「刚整理完照片想给你看」） | 有 | **无** |
| 聊天写记忆、纠错、原始档案 | 有 | 有 |
| 聊天引起的情绪变化 | 有 | 有 |
| 聊天中形成的承诺 / 跟进（「面试完问问你」） | 有，受「主动消息」开关约束 | 有，受「主动消息」开关约束 |
| 回复时注入当前活动 / 天气 | 有（需要时） | **不注入**，提示词里不出现世界状态 |

关闭后角色就是「有记忆、有情绪的聊天对象」，不再假装自己在过日子。

### 1.2 与其他开关的关系

三个开关互相独立，不嵌套：

| 开关 | 管什么 | 现有对应 |
|------|--------|----------|
| `worldline_enabled` | 世界线 tick、日计划、天气、扰动、世界经历派生的意图 | 新增 |
| 主动消息 | 是否允许角色先发消息（无论来源是聊天承诺还是世界经历） | 现有 `greet` |
| 朋友圈 | 是否允许发帖 | 现有 `moments_on` |

例：世界线开、朋友圈关 → 角色照常生活，但不发帖。世界线关、朋友圈开 → 没有世界经历可分享，**实际不会自动发帖**（旧的 `moment_daily` 定时发帖会在阶段 4 移除，不保留为关闭世界线后的兜底）。

### 1.3 切换行为

- **开 → 关**：停止该人设的世界线调度；未执行的「世界来源」意图标记为 `cancelled(reason=worldline_off)`；世界状态和已发生事件**保留不删**（看板可查历史），只是不再推进、不再注入。聊天来源的意图不受影响。
- **关 → 开**：按当前真实时间重新对齐，DSH 生成当天剩余时段的计划；**不补发**关闭期间的问候 / 动态，不把关闭期间写成「发生过的经历」。
- 首次开启（新人设或老人设迁移）：先做一次世界初始化（见 4.1），初始化完成前按关闭处理。

### 1.4 成本

世界线是模型调用的主要新增来源，开关也是成本控制手段。粗估开启时单个人设每天：1 次日计划 + 若干次局部重规划 / 分享判断 / 简短反思，约 5～10 次 DSH 调用（以阶段 3 观察模式实测为准）。关闭时这部分为 0。

## 2. 现状对照（与期望的偏差）

依据 2026-10-27～28 代码与 Flash Next 机制压测，阶段 0 需再核对。

| 主题 | 当前实现 | 期望 | 结论 |
|------|---------|------|------|
| 身份 | `personas` 已按 `user_id` 隔离；记忆 / 情绪 / 调度都绑 `(user_id, persona_id)`；没有跨用户共享的模板表 | 每人设一个实例 | **现有 `persona_id` 直接当实例 ID**，不新增 `companion_instance_id`；以后真要共享模板再加 `persona_template_id` |
| 世界线 | 不存在；管理台「世界线」Tab 是 Neural Field **纯前端模拟** | 可开关的后端运行层 | 全新建设；演示 Tab 后续改为读后端状态 |
| 事件 | 聊天、调度、朋友圈、抽取各走各的 | 统一事件入口与回流 | 主要缺口 |
| 调度器 | 进程内 30 秒循环 `start_scheduler`，跑 `greet_*` / `moment_daily` 配方 | 世界线按「下次唤醒时间」推进 | **可复用这个循环**，不需要新进程 |
| DSH 调用 | `dsh_turn(_stream)` 带 `conversationId`、显式 `history`、`instructions`、`system`；有 `interrupt`；抽取已用独立 `sys-mem-*` 会话 ID | 按用途隔离、上下文受控 | 用途隔离已具备基础；**DSH 是否还按 conversationId 自带历史需核实** |
| 记忆权威 | `memory_facts` + FTS + suppress + heat；兼容双写 `memories` | 保留，补来源 / 对象 / 时间 / 修订 | 结构可用 |
| 抽取 | 聊完 / 语音后同步 `extract_and_store`；v2 提示词 + 规则兜底；单次最多 3 条；失败静默 | 显式操作当轮提交回执；普通抽取进可重试任务 | 未完成 |
| 原始档案 | 聊天 `messages` 有；没抽成事实的内容基本找不回；语音转写归档链路弱 | 所有输入先归档，抽取失败不丢 | 缺 |
| 检索 | 默认 `rrf_gated`（FTS + 词面 RRF + 空召回不塞热记忆）；CJK bigram 只在查询端；FTS 用 `unicode61`；词面通道扫 `list_active(limit=500)`；无向量 | 精确 + 词面 + 语义三通道，无隐性条数边界 | 空召回污染已缓解；**500 上限、索引端分词、语义通道是硬伤** |
| 纠错 | `MemoryStore.correct`（supersede + suppress）存在；聊天主路径**不会**因「更正」前置纠错 | 显式纠正先提交再回复 | 同轮仍可能用旧名（压测已见） |
| 上下文 | 记忆约 ≤8 条 / ≤1200 token；历史、插件 snapshot、工具未统一计量 | 整次输入统一编译与预算 | 只管了记忆这一段 |
| Snapshot | FastAPI 组装 + DSH `product-companion` 曾二次注入 | 一次请求只注入一份 | **阶段0确认重复**；默认 `PRODUCT_COMPANION_INJECT=0`，由 ContextCompiler 唯一组装 |
| `pause_memory_read` | companion API 会清空 memories；聊天主路径未统一检查 | 所有读路径一致 | 阶段1 ContextCompiler 收口 |
| 部署 | 单进程 uvicorn | 人设串行锁 | **阶段0确认单进程**，用 asyncio 锁 |
| 忙时回复 | （旧稿曾写立即响应） | 忙只影响措辞，不拖延 | **已锁定**：立即回复 + 表达指引 |
| 情绪 | 六维 + 读时衰减；注入一句数值；**聊天不自动 `propose`** | 事件驱动评估，编译成表达策略 | 链路基本是展示 / 手动 |
| 成长 | 三模式已有 | 有证据的小幅修订 + 撤回 | 模式在，证据链缺 |
| 朋友圈 | `moments_on` → `moment_daily` 定时 LLM 发帖；发完 `add_memory("我发过朋友圈…")` | 世界经历 → 分享意图 → 校验 → 发布 | 入口要换；发布函数可复用；「发帖升格记忆」要改成只记发布事件 |
| 主动消息 | `greet_*` 配方 + `companion_followups` 初版 | 统一 `action_intents` | followup 演进为意图，不另造一套 |
| 压测 | Flash Next 抽取命中约 3%、baseline 空召回正确率 0 | — | **只代表测试模型**；阶段 0 用生产 DSH 重测 |

技术栈：第一阶段继续 **FastAPI + SQLite + DSH**，模块化单体。TS 迁移保留为同数据契约的后续项。不引入 Mem0 / Graphiti / Generative Agents 任一框架作为运行时依赖，只借鉴设计（见第 15 节）。

## 3. 可实现性评估

评级：**高** = 现有代码基础上直接可做；**中** = 可做但有明确风险或需要实测；**低** = 当前不建议做或需前置条件。

| 项 | 评级 | 依据与风险 | 建议做法 |
|----|------|-----------|----------|
| 世界线开关与停 / 启语义 | 高 | 纯业务状态 + 调度过滤 | 阶段 2 随事件层一起加字段 |
| 世界线 tick | 高 | 复用 30 秒调度循环；每人设存 `next_wake_at`，到点才处理 | 不常驻 LLM；确定性推进全部走代码 |
| DSH 世界初始化 / 日计划 | 高 | 单次结构化输出，失败可重试；每人设每天 1 次 | 输出 JSON + 程序校验；人设已写明的字段不许覆盖 |
| 局部重规划（天气、聊天打断） | 中 | 触发条件要收敛，否则调用量和计划抖动都会失控 | 只在活动前置条件失效 / 重要聊天事件时触发；同一原因有冷却 |
| 天气 | 高（模拟）/ 中（真实） | 真实天气需外部接口和地点；失败要能标「未知」 | 默认**模拟天气**；真实天气作为可选数据源（如免 key 的公开气象接口），按人设地点取 |
| 随机扰动 | 高 | 规则表 + 概率 + 冷却，结果落库 | 先做小规则表，不让模型自由编扰动 |
| 原始档案 | 高 | `messages` 已有；补世界事件表、语音最终转写、工具结果 | 世界事件与聊天消息分表，统一事件 ID |
| 显式记忆操作前置 | 中 | 需识别「记住 / 更正 / 忘掉」；复杂句要额外一次短 DSH 调用，增加这类消息的首字延迟 | 规则命中才触发；模型解析不明确时进待确认，不假装完成 |
| 可重试抽取任务 | 高 | 已有调度循环可跑任务；只是把同步调用改成入队 | `pending → processing → succeeded / retrying / failed`，带游标 |
| 结构化事实（主体 / 属性 / 值 / 有效期） | 中 | 依赖 DSH 抽取输出稳定；「另一只狗」这类对象消歧本质困难 | 结构化字段可空，退化为文本事实；对象不确定时新建并标「待合并」，不自动覆盖 |
| 去掉 500 上限 | 高 | 根因是词面通道全量扫描；FTS 已覆盖全部 | 写入 FTS 时同时写入 CJK bigram 切分文本，让索引端与查询端一致；词面打分只对 FTS 候选做 |
| 语义检索 | 中 | 需要本机 embedding 模型（BGE-small-zh 量级 CPU 可跑）；效果需按本项目测试集实测 | 优先用**已接入的 sqlite-vec**，向量与事实同库，比外挂 Faiss 少一套一致性问题 |
| 集合查询（列出全部编号） | 高 | 精确筛选 + 分页即可 | 识别「列出 / 全部 / 有哪些」走工具式查询，不占普通 8 条预算 |
| 热度规则修正 | 高 | 改加温来源即可 | 自动注入、助手复读、看板浏览、自写朋友圈不加温 |
| `ContextCompiler` 与整次预算 | 中 | FastAPI 已显式传 `history`，可控；风险在 DSH 是否另存会话历史、插件是否二次注入 | 阶段 0 先测清；若 DSH 自带历史无法关，按条数 / token 定期轮换 conversationId 并从权威状态重建 |
| DSH 用途隔离 | 高 | `conversationId` 已按用途区分（抽取用 `sys-mem-*`） | 固定命名：`chat` / `mem` / `plan` / `replan` / `reflect` / `share` |
| 情绪自动评估 | 中 | 每句都评估会加延迟和成本 | 普通承接不评估；重要事件评估与检索并行，超时沿用旧状态；多数情况回复后异步评估，作用于下一轮 |
| 情绪 → 表达策略 | 高 | 把六个数字编译成一两句表达指引 | 规则模板生成，不额外调模型 |
| 统一意图与行动出口 | 高 | 由 `companion_followups` 演进；执行器复用现有发消息 / 发帖 | 意图带来源（聊天 / 世界），世界线关闭时只取消世界来源 |
| 经历驱动朋友圈 | 中 | 「值得分享」判断质量依赖模型；要防止私聊内容上公开动态 | 观察模式先只记录「本来会发」；私聊来源事件默认禁止进入分享素材 |
| 并发与一致性 | 中 | SQLite 单写者；若服务是单进程，按人设 asyncio 锁 + 版本校验足够；多 worker 需库内租约 | 阶段 0 确认 chat-api 进程数；模型调用一律放事务外 |
| 重启恢复不重复行动 | 高 | 意图 / 行动有状态与幂等键即可 | 恢复时过期意图直接取消，不补发 |
| 人格成长证据修订 | 中 | 价值高但不阻塞闭环 | 放阶段 5 |
| 模板 / 实例拆分 | 低（不需要） | 现在没有共享模板需求 | 不做，见第 2 节 |
| 虚拟电脑 / 手机作为行动执行器 | 低（本期不做） | 前置是意图与行动出口稳定 | 闭环稳定后再接 |

**结论：** 闭环整体可实现，没有阻塞项。风险集中在三处，都放在阶段 0 / 1 先验证：DSH 会话历史是否可控、生产 DSH 抽取质量、显式记忆操作对首字延迟的影响。

## 4. 整体架构

### 4.1 分层

| 层 | 职责 |
|---|---|
| 接入与网关 | 登录、文字 / 语音、投递；入口统一转成事件 |
| 基础状态与记忆 | 原始经历、事实、人设、情绪、计划、修订；SQLite 为唯一权威 |
| 世界线运行层（可关闭） | 时间推进、活动生命周期、天气、扰动、到期检查 |
| DSH 驱动层 | 理解、规划、意图、抽取、回复；经 `DshAdapter` 按用途隔离 |
| 状态提交与行动 | 校验提议、短事务提交、执行发消息 / 发帖 / 工具 |
| 展示 | 聊天、朋友圈、世界线与陪伴看板，只读已提交状态 |

原则：**模型文本不等于事实成立。** 「准备发朋友圈」是意图，发布记录写入成功才算已发布；「准备整理照片」是计划，活动完成事件提交后才算经历。

### 4.2 统一流程

```text
用户消息 / 语音 ──────────────┐
时间·天气·扰动（世界线开启时）─┼→ 统一事件入口 → 保存事件 + 读当前状态
活动 / 行动执行结果 ──────────┘          ↓
                               需要模型判断？
                               ├─ 否 → 规则计算
                               └─ 是 → DSH（理解 / 规划 / 表达）
                                          ↓
                               校验并提交状态与意图（带版本）
                                          ↓
                               行动执行 → 回复 / 主动消息 / 朋友圈
                                          ↓
                               结果回流为事件；更新记忆；推送看板
```

世界线关闭时，第二路输入不存在，其余流程不变。

## 5. 世界线（开启时）

### 5.1 初始化

DSH 根据人设生成一份**结构化、可编辑**的初始世界：地点与时区、居住环境、职业背景、作息、兴趣、中长期目标、当前处境、情绪基线、主动程度。

规则：

1. 人设里已写明的优先，模型只补空缺。
2. 补出的背景标记为**虚构世界设定**，与用户现实事实分开存。
3. 初始化结果带版本落库；之后只通过事件更新，不再每轮重新生成背景。

### 5.2 三类持久物

| 类别 | 含义 | 示例 |
|------|------|------|
| 已发生事件 | 可回溯的经历 | 因下雨取消了散步 |
| 当前状态 | 现在的处境 | 在家整理照片 |
| 未来计划 | 还没发生 | 晚上继续整理相册 |

计划不提前写成已发生事实。问过去查事件，问「等会儿做什么」读计划。

### 5.3 三级规划

1. **持续目标**：跨天保留，完成或取消才结束。
2. **当天粗计划**：每天一次 DSH 调用，几个时间块。
3. **近期具体活动**：只细化当前和下一段，带预计时长、打断策略、结束条件。

活动状态：`planned → running → completed`，可 `running → suspended → running`，或 `cancelled / failed`。

### 5.4 推进规则

- 计时、情绪衰减、意图过期、活动到点结束：**代码处理**，不调模型。
- 只在需要新选择时调 DSH：日计划、前置条件失效（如下雨影响户外）、重要聊天事件打断、值得分享或反思的经历。
- 天气：程序判断条件（在下雨、户外受限），DSH 按人设给调整方案；天气记录来源（模拟 / 真实 + 观测时间）；真实天气获取失败标「未知」，不编造。
- 扰动：小规则表，受地点 / 活动 / 人设约束，有概率与冷却，结果落库，重启不重新抽签，不改写用户现实信息。
- 聊天进入世界线：判断是否打断当前活动、是否改变关注点、是否让某个待执行意图失效。**聊天立即响应**；「正在忙」只写入表达指引（是否口头解释看人设），**不** sleep / 排队拖延回复。
- 后端停机恢复：按真实时间结算衰减，过期意图取消，重新规划剩余时段；不补发问候，不把没执行的事写成已完成。

## 6. 意图与行动

所有主动行为先形成意图，再判断，再执行：

```text
intent_id, persona_id, source(chat | world), trigger_event_id,
action_kind, reason_summary, not_before, expires_at,
preconditions, status
```

- **执行前复查**：用户是否已主动说明、是否正在聊（可合并进当前回复）、是否刚联系过、是否过期、开关是否允许、是否适合公开。
- **结果**：现在执行 / 稍后 / 合并进聊天 / 放弃。产生意图不等于一定执行。
- **朋友圈**：经历 → 是否值得分享 → 意图 → 校验 → 发布。「一天最多一条」是上限不是指标；发布后只记录「某时发布了某条动态」，**不把文案内容升格为事实记忆**；私聊来源的内容默认不进入分享素材。
- **主动消息**：来源可以是聊天承诺（世界线关闭也有效）或世界经历（世界线关闭则不产生）；都受主动消息开关约束。
- **迁移**：`companion_followups` 演进为 `source=chat` 的意图；阶段 4 移除 `moment_daily` 定时发帖，发布函数保留作为执行器。

## 7. 记忆底座（优先实施）

### 7.1 分层与来源

逻辑层：原始档案 · 工作记忆 · 事实 · 情节 · 人格与关系 · 反思。不要求各自一套库。

来源必须可区分：用户明确说过 / 工具观察 / 虚构世界 / 助手说过 / 模型推断。**助手复述一句话不会让它变成用户事实。** 世界线产生的经历标记为虚构世界来源，回答「你今天做了什么」时可用，回答用户现实问题时不可当证据。

### 7.2 写入

1. 所有输入先进原始档案，不依赖抽取成功。语音存最终转写。
2. **显式操作**（记住 / 更正 / 忘掉）：保存 → 识别 → 校验目标 → 提交 → 拿到成功回执 → 再生成回复。只有提交成功才能说「记住了」「改好了」；解析不明确就进待确认。
3. **普通抽取**：回复后入队，可重试，带来源事件、抽取版本、处理游标、尝试次数、错误原因。单批上限 3 条，剩余内容下一批继续。
4. 「没有长期信息」「输出格式错」「用户要求记住但模型返回空」分别记录；后两种算失败，进入重试。

### 7.3 纠错

事实字段补充：`subject_id, predicate, value, scope, source_event_ids, valid_from, valid_to, revision, supersedes_id`（结构化字段可空，退化为文本事实）。

| 输入 | 处理 |
|------|------|
| 「本来就叫来福，你记错了」 | 旧事实作废，新事实生效 |
| 「改名叫来福了」 | 记改名事件，旧名保留有效期 |
| 「另一只狗叫来福」 | 新对象，不覆盖 |

- 编号、数字、日期、否定词不参与近义去重（「玉兰 00～29」是 30 条）。
- 纠正一次提交要覆盖：权威表、FTS、相关缓存 / 摘要、向量索引（异步时入 prompt 前回查权威状态）、阻止旧抽取任务写回。
- suppress 尽量针对具体事实，不整句屏蔽。

### 7.4 热度

热度 · 重要性 · 证据可靠度 · 当前相关性分开。

加温：用户再次主动提起、用户确认、任务中实际用上。  
**不加温**：自动注入、助手复读、看板浏览、模型自写朋友圈、后台反思改写。  
低温记忆仍须能被精确查询召回；热度不绕过相关性门控。

### 7.5 检索

| 通道 | 解决什么 | 实现 |
|------|---------|------|
| 精确 | 编号、姓名、对象、时间 | 结构化字段 + 规则抽取查询实体 |
| 词面 | 关键词 | FTS5；**索引端也写入 CJK bigram**，与查询端一致 |
| 语义 | 转述、口语（「毛孩子」） | sqlite-vec + 本机中文 embedding，实测后启用 |

- 三路各自有界取候选，**基于全量索引**，去掉 500 条扫描。
- 先按人设、来源域、有效状态过滤，再 RRF 融合；允许返回空。
- `rrf_gated` 保留为对照方案。
- 普通聊天 8 条预算保留；「列出全部 / 有哪些」走集合查询与分页。

## 8. 上下文控制

一次 DSH 调用的输入不只有记忆：还有 DSH 侧历史、插件注入、人设、世界状态、工具定义与结果。只卡记忆 1200 token 不算解决。

- **`ContextCompiler`**（由 `build_companion_snapshot` 扩展）：每次请求唯一组装一次，记录 `snapshot_id`、各状态 revision、选中证据 ID、分节 token。插件若读 snapshot，必须复用同一份，不再二次注入。
- **预算**：`输入 ≤ 模型上下文上限 − 输出预留 − 安全余量`，按节分配：核心人设、成长摘要、世界状态（世界线关闭时为 0）、情绪表达指引、最近对话、相关记忆、工具。超出时优先保留当前问题、明确纠正和当前任务相关内容。
- **用途会话**：`chat` / `mem` / `plan` / `replan` / `reflect` / `share` 各用独立 conversationId，共享权威状态，不共享中间输出。
- **DSH 侧历史**：阶段 0 测清 DSH 是否按 conversationId 自行累积历史。若可关闭，以 FastAPI 显式 `history` 为准；若不可关闭，按 token / 条数定期轮换 conversationId，从权威状态重建。

验收标准：**数据库记录增长，单次输入不随之线性增长。**

## 9. 情绪与成长

- 三个时间尺度：稳定人格（很慢）· 持续处境（中）· 短时情绪（快）。
- 基线按人设设定，不默认全 35；六维独立，不归一。
- 有意义事件（聊天或世界）→ 简短结构化评估（情绪变化、关注点、是否重规划、候选意图、原因）→ `AffectService.propose`（限幅、幂等、版本）。
- 约束：同一原因不重复刺激；用户难过不等于角色同等难过；普通承接（「嗯」「哈哈」）不评估；评估多数在回复后异步完成，作用于下一轮。
- 注入方式：把情绪编译成一两句表达指引，例如「有点担心对方，先回应他说的事，少开玩笑」，代替直接塞六个数字。世界线关闭时指引里不出现当前活动 / 天气。
- 成长：保留三模式；修订记录写清改了什么、依据哪些经历、修改前后版本、如何撤回。关闭成长只冻结人格，事实、情绪、世界线照常。

## 10. 统一处理流程

### 10.1 聊天回合

1. 确认用户与人设 → 2. 保存原始输入 → 3. **显式记忆操作前置提交** → 4. 读相关记忆（世界线开启时加世界状态）→ 5. 必要时短评估 → 6. 提交情绪 / 意图变化 → 7. `ContextCompiler` 组装 → 8. DSH 流式回复 → 9. 保存实际回复与投递状态 → 10. 后台抽取入队 → 11. 取消 / 合并 / 新增意图。

### 10.2 世界线事件（仅开启时）

提交事件（如活动完成）→ 更新当前状态 → 写情节记录 → 需要时调 DSH 提出下一步 → 校验提交意图 → 到执行时间复查条件 → 执行 → 结果回流。

### 10.3 一致性

- 模型调用在数据库事务之外；写入用短事务 + 版本校验。
- 每人设串行提交（单进程用 asyncio 锁；多 worker 用库内租约，阶段 0 确认部署形态）。
- 旧提议依赖的状态已变（如用户已说了面试结果）→ 重新验证或丢弃。
- 外部行动带稳定 `action_id`；超时且结果未知时先核查再重试。

## 12. 看板

- **当前生活**（世界线开启时）：时间、地点、天气、正在做、下一项、刚改变的计划；关闭时显示「世界线已关闭，仅对话驱动」及关闭前的历史。
- **情绪**：六维平滑变化 + 文字概括 + 最近影响因素。
- **意图**：想做 / 等待条件 / 执行中 / 已完成 / 已取消，带原因（如「用户已主动说明，取消追问」「世界线关闭」）。
- **记忆**：类型、来源、有效期、版本、热度、本轮为何被召回、是否已纠正。
- **运行问题**：抽取失败、未处理事件、意图取消、上下文裁剪、DSH 耗时与 token。

前端可做插值动画，不自行编造状态。现有 Neural Field 演示在接通后端前保留「模拟」标注。

## 14. 验收场景

**记忆**：连续记 30 个编号不误合并 · 改名保留有效期 · 纠正后同一轮不用旧名 · 抽取失败原文不丢且可重试 · 查询不存在编号不用热记忆填补 · 1 万条噪声后仍能查到旧事实 · 「列出全部」完整返回 · 自动注入不升温 · 纠正后旧任务不写回 · 语音信息可追溯来源。

**世界线**：下雨只调整相关计划 · 聊天打断活动可暂停 / 恢复 · 用户已说面试结果则追问意图取消 · 当天无值得分享的经历就不发帖 · 私聊内容不进朋友圈 · 重启不重复发消息、不重新抽扰动、不补发过期问候。

**开关**：关闭世界线后不再产生天气 / 日计划 / 扰动 / 世界来源意图，回复提示词中不含世界状态，聊天记忆与情绪照常 · 关闭时待执行的世界意图被取消、聊天意图保留 · 重新开启后从当前时间对齐，不补发 · 关闭世界线 + 开朋友圈不会出现定时发帖。

**整体**：长期聊天单次输入保持在预算内 · 关闭成长只冻人格 · 同一模板多用户互不串数据。

指标拆开记录：写入成功率 · 候选召回率 · 上下文入选率 · 回答正确率；另记首字延迟、队列延迟、每日 DSH 调用数（分世界线开 / 关）、重复行动数、单次上下文大小。
